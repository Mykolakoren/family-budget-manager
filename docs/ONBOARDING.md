# Onboarding Overview

Этот репозиторий пока находится на раннем этапе: в основной ветке `work` хранится только базовый `README.md` с кратким описанием идеи мультиплатформенного менеджера семейного бюджета. Ни серверной, ни клиентской реализации пока нет.

## Что есть сейчас

- **Коммиты**. В истории всего три коммита: первоначальный план, стартовый коммит и merge pull request, зафиксировавший планы по созданию структуры проекта.
- **Файлы**. На момент проверки в корне лежит только `README.md`.

## Какой структуры ожидать

Так как код ещё не добавлен, структура проекта предстоит определить. На основе целей (мультиплатформенный бюджетник) стоит заранее обсудить и зафиксировать:

1. **Разделение на модули** — например, backend API, frontend (web / mobile), слой синхронизации и общие модели.
2. **Технологический стек** — язык и фреймворки для каждой платформы.
3. **Стандарты разработки** — гайдлайны по стилю кода, тестированию и CI.

Создание этих артефактов до начала активной разработки поможет удерживать проект в понятной структуре.

## Подсказки, с которых стоит начать

1. **Внимательно изучить историю коммитов** (`git log`) — там можно найти исходные намерения и комментарии авторов.
2. **Обсудить и задокументировать архитектуру**. Хорошей отправной точкой станет подготовка архитектурной схемы и описания каталогов. Можно оформить это в `docs/ARCHITECTURE.md`.
3. **Согласовать процессы** — определить формат ведения задач, ревью и релизов, прежде чем появится код.

Когда появятся дополнительные файлы (например, спецификации или прототипы), расширьте этот документ ссылками на них, чтобы новым участникам было проще подключаться.
